Almonium · visual system extraction

The implicit design system behind the current interface

Reconstructed from ten interface screenshots (login, onboarding step 3, avatar modal, Profile / Account / Learning settings, Play, Read index, Book detail, Compare Plans) and cross-checked against the shipped stylesheets in almonium-fe. No screen is proposed here; nothing is modernised. Where the screenshots and the code disagree, both readings are recorded.

Evidence levels: Observed directly visible, or literal in the stylesheet Inferred a rule read off repetition across ≥2 screens Unknown not determinable from static screens
1

Visual character and product personality

The product reads as a warm, bookish, slightly whimsical study companion — not a gamified streak machine and not an enterprise dashboard. Four traits carry that character:

  • Paper-warm, never white. Every page sits on the same off-white cream; white is reserved for raised cards. Visible on all ten screenshots. Observed --main-bg-color: #F9F6F5
  • Literary serif voice. The wordmark, the top navigation and the game titles are set in a serif/display face while UI controls are sans — the product signals "reading" rather than "app". Observed --font-family: Cambria…serif
  • Very round geometry. Pills, capsules and 20–35px card radii everywhere; there is effectively no square corner in the product except the tiny CEFR/level chip. Observed
  • Playful, illustrated mascots. Cartoon animal avatars, a hand-drawn vintage-engraving illustration set for games, drifting translucent card particles behind auth/onboarding. Personality is delivered by illustration, not by UI decoration. Observed
  • Plum/aubergine as the single brand hue, with raspberry as its action shade. Nothing in the product uses a corporate blue except third-party auth and informational accents. Inferred

Copy tone matches: second person, short, warm, occasionally teasing ("Why so mysterious? Share your interests with us!", "Almo will challenge your knowledge…", "Who will outsmart the other to claim victory?"). Feature names are single verbs — Discover, Review, Read, Play.

Layout, containers, grid, alignment, spacing rhythm

  • One base container per page: full width, min-height = viewport − header, ~1.2rem padding, cream background, contents centred. Section pages override it to top-align and stack with a 2em gap. Observed
  • Settings uses a masonry column layout, not a grid: a 820px-max, 2-column CSS column flow with 1rem gutters and 400px blocks that avoid breaking. This is why the Profile screenshot has cards of unequal heights stacking left and a taller Interests card on the right with a ragged bottom edge. Below 820px it collapses to one column. Observed
  • Catalogue pages use auto-fit grids of fixed-size cards, centred on small screens and left-aligned from 600px up: games minmax(300px, max-content) with 280×400px cards; books minmax(14rem, max-content) with 14rem×22rem cards. Card margin (10–20px) does most of the visual spacing; grid gap is only 6px. Observed
  • Detail pages are two-column and top-aligned: a fixed ~250px left rail (cover + one full-width primary action) and a fluid right column of stacked facts, gap 2rem; it stacks vertically under 768px. Observed
  • Spacing rhythm is rem-based and coarse: 0.2 / 0.5 / 1 / 1.5 / 2rem, with 1rem as the default gap inside a card and 2rem between major blocks. Onboarding cards use padding 1.5rem and gap 2rem; settings blocks padding 1.3em and gap 1em. There is no 4/8px token scale — spacing is authored per component. Inferred
  • Alignment convention: content left-aligned inside cards; card titles flush left at the top; the row's action (edit pencil, chevron, toggle) pushed to the far right with margin-left:auto. Modals and auth cards centre everything. Inferred
  • Onboarding cards are content-sized, min 20rem / max 30rem wide (40rem when the step shows plans) — they never stretch to fill. Observed
  • The exact page max-width for Read / Play / Book is Unknown — those grids are full-bleed with only container padding, so on very wide monitors the behaviour cannot be judged from a 1920px screenshot.

Border, radius, shadow, elevation, surface

RADIUS LADDER

4px inline level chip · 8px discount badge · 15–18px status box, filter pad, small pill · 20px settings block · 25px provider tile, popover, plan card · 25–35px generic card · 50em / 9999px all buttons, chips and toggles.

TWO SHADOWS ONLY

Ambient: 0 1px 3px rgba(0,0,0,.1), 0 1px 2px -1px for cards, badges, the logo, the avatar. Media: 0 2px 5px 1px rgba(0,0,0,.15) for game and book cards. Popovers get a third, deeper 0 4px 8px rgba(0,0,0,.15).

ELEVATION = SHADOW, NOT BORDER

Raised things have a shadow and no border. Bordered things (provider tiles, outline buttons, chips) are flat and interactive. The only element with both is the language badge and the popover.

FROSTED OVERLAYS

Text over artwork sits on rgba(255,255,255,.5) + backdrop-filter: blur(6px) — book titles, the progress ring. Never a solid bar.

DASHED = EDITABLE / EMPTY

A 1px dashed border marks "add / edit / drop here": the Interests Edit chip, the "+ Order" chip, the file drop-zone. Solid borders are committed values.

SETTINGS EXCEPTION

Settings blocks deliberately kill the card shadow (box-shadow: unset) and use radius 20px — the section reads as flat panels on cream rather than floating cards.

All of the above: Observed in both screenshots and stylesheets.

7

Component patterns

Buttons — four appearances, no more

gradient

Full-width pill, plum→raspberry, white bold 16px, padding 1.1rem 1.5rem, radius 9999px. Hover = opacity .75. The single commit action.

bw (outline)

1px #3d3d3d, transparent, 14px/550, padding .5em 1em, pill. Hover inverts to dark fill + white text. Secondary actions: Manage, Link, Save.

underline

Underlined black label, no chrome; hover swaps the underline for a #f0f0f0 pill. Tertiary/toggling actions: Hide, Unlink.

text

Coloured label only ("Mark all as read"), 16px/550, drops to opacity .5 when busy or disabled.

Danger is a fifth, page-specific variant: white fill, 1px #fa4666, radius 35px, padding 15px 30px, bold 15px, icon + label, hover fills raspberry. Observed

Icon buttons

A 40×40px circle, 1px #3d3d3d border, white fill, a 24px Lucide icon at stroke-width 1 inside; hover inverts to a dark fill. Used for every "edit this row" affordance (Profile, Username, Email, Password, I Know) and for "+ add". Bare Lucide icons (no circle) are used for share/QR/link, bookmark and downgrade. Loading swaps the glyph for a centred spinner in place. Observed

The icon set is mixed: Lucide (stroke, 1px) in the shell and settings rows, but Font Awesome solid glyphs in the settings tabs and the numbered stepper avatars. Observed

Inputs

Pill-shaped fields (radius 2rem/3rem) with a white fill and a very soft shadow instead of a visible border; label sits above the field in 1.1rem/550 ("I'm fluent in"). Multi-value fields hold removable chips inline plus a trailing ✕ (clear all) and ▾ (open list). Search is a pill with a leading magnifier and placeholder-only labelling. Selects are compact pills with a chevron, sized to content (6–9rem). Focus/accent colour inside forms is overridden to a deeper plum (#5A1A74); error state is #ac1c1c for both border and message. Observed

Cards — three distinct kinds

  • Settings/content panel: white, radius 20px, no shadow, padding 1.3em, gap 1em, bold 16px title flush top-left, one row of content, action right-aligned.
  • Media card: fixed size, radius 1.1–1.5rem, image bleeds to all four edges, metadata in a frosted strip pinned to the bottom, status badges absolutely positioned in the corners (level top-right, progress/parallel top-left), hover scale 1.01.
  • Illustrated game card: 280×400, radius 25px, a per-game pastel background colour tinting both the illustration area (70%) and a slightly translucent caption area (30%), centred display title + left-aligned 15px description in #666.

Note: the game card's description area is a fixed 30% and the copy is clipped rather than truncated in the Play screenshot ("How far can you climb?" and "victory?" are cut off) — an observed defect, not a rule. Observed

Tabs and segmented controls

Two different mechanisms, used consistently for two different jobs. Route tabs (Settings) are centred, icon + label, transparent, with a plum underline under the active item and a full-width hairline beneath the strip. Filter tabs (Play: All / Solo / PvP) are a white "pad" with radius 18px holding pills; the active pill takes a pale pink fill (#ffeefb) with raspberry bold text (#8F2356). Segmented switches (Monthly / Yearly) are a bordered radius-10px group where the active half is white-raised and the inactive half is transparent, with a pink discount badge riding the inactive label. Observed

Chips and badges

  • Data chip (interest, language, level): pill, auto-generated pastel fill, dark text, no border, 0.5em gaps in a wrapping row. A chip may nest a micro "inner-text" box (1px solid, radius 4px, 0.55rem uppercase) for a level range.
  • Action chip: same pill but transparent with a 1px dashed #3d3d3d border and a small leading icon — Edit, Add, + Order.
  • Squared badge (.badge-btn): radius 25%, Arial, +1px tracking, 1px coloured border, shadow, cream fill — the navbar language code and the CEFR level. Hover scale 1.02.
  • Status box: radius 15px, tinted background, tiny circular glyph + 10px/650 uppercase label (VERIFIED, pending).
  • Corner badge: solid orange pill, white bold 14px, radius 20px, absolutely positioned on artwork (level range on covers).
  • Notification dot: tiny red dot pinned 2px/2px inside the top-right of the host icon or avatar.
  • Premium star: 2.5rem gradient circle with a glow shadow, pulsing on hover.

Menus

White popover, radius 25px, pink hairline border, 0.5rem vertical padding, 20rem-wide rows. Row = 24px Lucide icon + label, radius-md, hover #f3f4f6. Groups are separated by a 1px #eaeaea rule; the profile menu leads with an avatar + username/email identity block. Right-click context menus on notifications use the same row grammar, with destructive items in raspberry. Menu bodies scroll at max-height 60vh with a custom 8px scrollbar. Observed

Modals

Radius 2rem sheet, min-width min(50rem, 60vw) for wide ones, background cream (Change Avatar) or light grey #f1f1f1 (Compare Plans) so that white content cards read as raised inside it. Header: centred, bold, clamp(1rem, 7vw, 2rem), 1rem padding, 2rem margin below. Close = grey circular ✕ top-right. Bodies split into a narrow left "current value" column and a wider right "choose" column separated by a 1px vertical divider with 1rem breathing room; below 780px the split becomes vertical and the divider becomes horizontal. Confirmations are a separate title + message + confirm-text modal, sometimes with a countdown before the destructive button arms. Observed

Information-density conventions

  • One concern per card. Settings never groups two unrelated fields; "Email and Password" is one card because they are one concern, and Level/Active sit in one card because both belong to the selected language. Observed
  • Loose overall, dense at the atom. Generous card padding and whitespace, but the atoms themselves are tight: 10px uppercase micro-labels, 0.7rem ratings, chips packed at 0.5em. Inferred
  • Facts are compressed onto one line with · separators rather than a definition list: "English B2–C1 · 255 pages · First published in 1872 · Translated by Anthony Matonak". Observed
  • Overflow is summarised, not scrolled: "+1 more" next to a language chip; a filter row rather than a table of options. Observed
  • Explanations are deferred to tooltips and (i) buttons, keeping the surface short; only genuinely constraining rules are printed inline ("Free plan lets you pick only 1 target language."). Inferred
  • Catalogues are cover-first: ~86% of a book card is artwork; text is minimal and overlaid. Density scales by adding cards, never by shrinking a card. Observed
9

Repeated interaction patterns

  • Read-then-edit rows. A value is displayed, and a circular pencil on the far right switches that row into edit mode in place. Saving is a "bw" Save button inside the same card. Observed (Username, I Know, Interests)
  • Inline optimistic actions with local spinners. Any icon or button can carry its own loading state — the glyph is replaced by a spinner and the label is made transparent, so layout never shifts. Observed
  • Hover-swapped labels. The same control changes its word on hover to reveal the inverse action (Hidden → Unhide). Observed
  • Micro-scale on hover — 1.01–1.09 depending on element size (cards 1.01, badges 1.02, menu icons 1.05, avatars 1.09) with a 0.2s ease. Nothing lifts or changes shadow. Observed
  • Dismiss by clicking outside. Every popover and dropdown closes on outside click; dropdowns also support arrow-key navigation with a focused-item style. Observed
  • Destructive actions are always two-step and always physically separated into a pink Danger Zone; a confirmation modal (sometimes countdown-gated) follows. Observed
  • Paywall as an interception. Locked capability is not hidden; it is shown with the constraint stated, and the Upgrade CTA opens the Compare Plans modal. Premium features are marked with ✨/gradient rather than a lock. Inferred
  • Filters are a single horizontal row of heterogeneous controls (search, radio, select, sort direction) that collapses to a column under 768px; results react immediately, with no Apply button. Inferred
  • Whether card hovers reveal extra affordances (the book caption strip has an opacity/transform transition defined) is Unknown from static frames.

Inconsistencies and uncertain interpretations

  • Three "selected" idioms (underline, pink pill, white segment) live within two clicks of each other. Deliberate per-context, but not a single rule.
  • Radius is not tokenised. 18, 20, 25, 28, 35px and 1.1rem/1.5rem/2rem/3rem all appear for card-like surfaces. Any new screen must pick by matching its nearest neighbour, not by a scale.
  • Two accent plums. #83397f is the global accent, but the Account tab overrides it to #5A1A74 locally, and the active nav link is #520f6a. Which is canonical is Unknown.
  • Two gradients for one meaning. The CTA gradient is defined once as #5A1A74→#8F2356 (left→right) but the onboarding Continue button in the screenshot reads darker on the left and brighter magenta on the right at a slight angle — the exact angle/stops per instance vary.
  • Danger red vs error red. #fa4666 (danger zone) and #ac1c1c (form errors) coexist; the distinction is destructive-action vs validation, but it is never stated.
  • Font mixing. Serif (brand), the library sans (UI), Arial (badges), and fantasy (game titles) — four families, one of them OS-dependent. The screenshots show game titles in a slab serif that will not reproduce on every machine.
  • Icon-set mixing. Lucide stroke icons and Font Awesome solid glyphs appear in the same viewport (settings tabs vs settings rows), so stroke weight and optical size are inconsistent.
  • Clipped copy on game cards (fixed 30% caption) and on book captions where the frosted strip overlaps the rating.
  • The Interests card breaks the "no border, no shadow" settings rule by being visually taller than its siblings in a masonry column, producing an intentional-looking but accidental asymmetry.
  • Hover-only affordances (share icons, "Hide", card scale) cannot be judged for touch parity from these screenshots — Unknown.
  • Not determinable at all: dark mode, focus-ring styling for keyboard users, transition durations beyond the 0.2–0.3s seen in CSS, mobile navbar layout, the Discover / Review / chat surfaces (no screenshot supplied), and real type sizes for the library-owned components (they inherit the component library's own scale).

Brand foundations — hue ramp, jurisdiction, type

The logo defines the palette

The emblem's ten blades ramp from raspberry to violet. Every brand hue in the product is already a sample from it — which is why #872657 and #612b5e feel native and the old cyan did not.

Rule: no brand hue may exist that is not on this ramp. Status colours (sage, amber, rose, info blue) are the only exceptions and are already fixed.

Calm by default, warm at the edges

Two registers coexist — bookish-intelligentsia and young-startup-playful. They are compatible only with a jurisdiction rule.

Calm — content surfaces

Reader, cards, review, library, settings, chat. Serif, cream, plum. No illustration, no emoji, no motion beyond state feedback.

Warm — contentless surfaces

Empty states, errors, 404, offline, loading, onboarding, earned celebration. Mascot lives here and only here.

The abstract emblem carries the intelligentsia signal; Almo carries the warmth. They never share a screen.

Type — two families, self-hosted, no system stacks

Verified in the repo: --font-family: Cambria, Cochin, Georgia, Times… is a fallback stack, not a choice — Cambria on Windows, Cochin on Mac, Times on Linux. Nine competing declarations exist across components, including font-family: fantasy in play, and the reader hardcodes Georgia/Palatino and ignores the variable entirely. Libre Baskerville is already installed via @fontsource but reaches only book covers.

Literata

Wordmark, page titles, section headings, book titles, all reading content, the word on a card.

Built for long-form screen reading. Variable weight. Full Cyrillic — non-negotiable given the UA/RU wedge.

IBM Plex Sans

Nav, buttons, chips, badges, metadata, form labels, counts, tooltips, eyebrow labels.

Cyrillic + Latin Extended for PL/DE diacritics. Mono sibling available for IPA and lemma forms. Not Inter.

Alternative serif if a cooler tone is wanted: Source Serif 4. Pick one, not both. Reader may let users override the reading face — offer three options, not a menu — but the default is Literata.

14

Premium as a material, not a colour

The cyan/violet neon was correctly removed — those hues are off-ramp and read as crypto/gaming to an audience that chose Almonium for not being gamified. But the behaviour was removed alongside the colour, which is why premium now reads as flat plum. Premium should feel like a different material: material is communicated by how a surface responds to light and touch, not by how loud it is.

Gradient

Sample from the emblem rather than from nearby: linear-gradient(135deg,#8F2356,#5A1A74). Richer than the current #612b5e→#83397f and provably on-brand.

Shine sweep — restore

Keep skewX(20deg), blur 6px. Highlight rgba(255,252,248,.22) not white .4. 900ms single pass on hover — drop the 5s infinite loop, which is what made it feel cheap.

Star badge — restore hover, not glow

No neon shadow. On hover: translateY(-1px) + rotate gradient 135deg→200deg over 400ms. Catches light like metal without emitting any.

Confetti — keep

On successful upgrade only. Celebration is rationed, not banned — rationing it to exactly one event makes it land. Fire once; never on revisit.

CTA hover — currently too timid
transform: translateY(-1px);
box-shadow: 0 6px 16px rgba(72,23,125,.28), 0 2px 4px rgba(72,23,125,.16);
transition: transform 160ms ease, box-shadow 160ms ease;
Reserve the gradient for premium — the structural fix

Premium went off-palette because gradient had already been spent on every action button, leaving nothing for the paid tier to differ by. Take it back: primary commit becomes solid #5A1A74 (still the one action per view — solid is if anything more decisive), and gradient becomes exclusively premium — upgrade CTA, plan card, star, avatar ring, nothing else. Premium then reads as different without leaving the ramp, and an entire signalling channel is recovered for the cost of one variable. It also dissolves the purple-gradient-AI-startup association, which came from frequency rather than hue.

Correction — the settings premium pill is a real button

It opens the same customer portal as Manage, so the earlier status-styled-as-action reading was wrong. The remaining problem is smaller: it is a filled gradient pill, which in this system means "the one commit action on this view," for a secondary, non-committing destination — and it duplicates Manage. Ship one control, not two: Premium as plain plum 550 status text, Manage as the only button. Not bold; status is a fact.

15

Mascot canon — Almo

The octopus is the right animal: nine brains and distributed cognition, eight arms for parallel texts, ink for writing, camouflage for adapting register. An owl maps to nothing and is Duolingo-adjacent. Keep the creature; fix the execution — currently three different octopuses across three screens, one of them coral (roughly plum's complement, so it reads as a foreign object), in a stock AI-render pose that violates the project's own "no AI art" decision.

Style

19th-c. engraved plate. Hatching, no airbrush, no gloss, no rim light. Merges with the vintage engravings already in the games.

Ink

Single colour, deep plum #612B5E, transparent background. Never coral, never full-colour, never two mascot hues in one product.

Set

Six to eight fixed poses, drawn once. Rest, reading, offering a card, searching, asleep, delight, waiting, greeting.

Placement

Empty states, errors, loading, onboarding. Never the landing hero — a cute mascot above the fold reads as a beginner app to this audience.

Consistency method: GPT-Image-1 exposes no seed, so prompt text alone never reproduces a character. Generate all six poses in one character-sheet render (identical by construction), crop them apart, then chain new poses by uploading the approved figure as reference — always referencing the original, never the latest output, or drift accumulates. Constitution

Rules every future Almonium screen follows

1

Cream ground, white float. Every page starts on #F9F6F5. White is only for raised surfaces. Never put a white page background behind content.

2

One primary action per view, and it is a solid plum pill — #5A1A74, radius 9999px, white bold 16px, padding 1.1rem 1.5rem, full width of its column. Below it: dark secondary solid, outline, underline, text. Gradient is not available to it — gradient means premium and only premium.

3

Round everything. Interactive elements are pills; containers are 20–35px; nothing below 15px except the 4px inline level chip and 8px micro-badges. No square corners.

4

Two families only: Literata for brand and reading, IBM Plex Sans for every control. Never set a form label or button in the serif; never set the wordmark, a heading or body text in the sans. No system font stacks, no third family.

5

550 for emphasis, 700 only for display. Body 16px/1.5, long-form 1.6, micro-labels 10px uppercase 650 with tracking.

6

One concern per card, bold 16px title flush top-left, content in a single row or wrapping chip row, the row's action pushed to the far right as a 40px circular outlined icon.

7

Spacing in rem steps of 0.5: 0.5 / 1 / 1.5 / 2rem. 1rem gap inside a card, 1.3em card padding, 2rem between blocks. Use flex/grid gap, never margins between siblings.

8

Elevation is shadow, hierarchy is not border. Two shadows only: ambient for cards, the slightly deeper media shadow for artwork. Hover changes scale (1.01–1.09), never shadow.

9

Categorical data is a pastel chip whose colour comes from its own label — languages, interests, levels. Do not hand-pick chip colours, and do not invent new semantic hues.

10

Dashed border = "add / edit / drop here". Solid = a committed value. Keep that contract.

11

Edit in place. Show the value, offer a pencil, swap the row into a field, save within the same card. No separate edit pages.

12

Every control owns its own loading state — spinner in place, label hidden, zero layout shift. Page-level waits use skeletons shaped like the real content, radius 12px.

13

Destructive actions are quarantined in a #ffe3e9 Danger Zone at the end of the column, with a raspberry outline button and a confirmation step. Never inline, never a primary.

14

Premium owns the gradient outright. No other element in the product may carry one. Plum gradient sampled from the emblem, plus one restrained response to touch — a single hover sweep, a lift, a rotating gradient. No glow, no loop, no off-ramp hue. Locked features stay visible with the limit stated in one plain sentence; upgrade is an invitation, not a lock icon.

15

Personality comes from illustration and copy, not from UI ornament. Mascots, engraved artwork, particles and a warm second-person voice — while the chrome stays quiet, round and cream.

16

No brand hue exists that is not on the emblem's ramp (#A1264C → #48177D). Status colours are the only exceptions and are already fixed. No black, no cyan, no invented accent.

17

Calm by default, warm at the edges. Surfaces holding real content are quiet — no mascot, no emoji, no ornament. The playful register is permitted only where there is nothing to read: empty, error, loading, onboarding, earned celebration.

18

Status never looks like action. A filled pill does something when clicked. Anything that merely reports a state is text, small-caps or a hairline outline — never a filled pill.
